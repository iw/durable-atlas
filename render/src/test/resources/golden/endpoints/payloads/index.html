An HTTP service is named after the first label of its host, or more labels where two hosts would share a name, or after the configuration key its targets start with where no host is configured. A client is one service per class named with --client, with one operation per name it is asked for.

What is read: the body a request sends and how it is made, the type the answer is read as and with which library, the parameters of the target with the types of what gives them, the arguments of a client's call, and the shape of each model in the sources. What is not: the services' own code and descriptions, an ObjectMapper configured in code, and JSON written by hand, which is shown as text.
